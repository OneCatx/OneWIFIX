## eSIM compensation

`main.api_esim_enable` first performs an idempotent live check under the reader lock: enabled-profile EID/ICCID **and physical `sim.read_card` ICCID** must agree before returning `already_active: true`. For mutation it captures the selected SE's actual EID and previously enabled ICCID using lpac **inside the same `hub.reader_lock` acquisition as enable**. A failed lpac enable, failed post-enable verification, failed bridge/line recovery, or request cancellation reads actual inventory again before deciding compensation. An absent/ambiguous EID, changed EID, missing old profile, or no previously enabled ICCID fails closed; no profile write is made to an unproven eUICC. Re-enable of the prior profile is followed by another EID/state read and native-card ICCID probe or modem bridge restart plus every allocated VPCD slot ICCID check. Only then are exact prior enabled flags restored; previously running lines restart only when their own stored ICCID matches the verified original profile. Compensation failure and original failure are both present in HTTP 503 detail and logs; successful rollback still returns non-success, never `ok: true`. Cancellation awaits compensation before releasing the switch lock and then propagates cancellation. Download/disable/delete LPA operations remain existing MDD behavior; no real eUICC writes were run.
