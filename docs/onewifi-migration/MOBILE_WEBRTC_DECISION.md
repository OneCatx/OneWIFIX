# Mobile SIP/WebRTC option — 2026-10-13
Status: APPROVED by user; implementing as part of the original migration. No production implementation existed at approval.
User asks whether mobile calls can use browser-style technology. Recommend both mobile apps use SIP over authenticated MDD WSS plus WebRTC media; browser retains JsSIP. Reuse UI and OS integrations (iOS CallKit/PushKit/Live Activity; Android Telecom/services/notifications). Replacing current SSE+PCM transport is a bounded call-subsystem change, larger than URL rewiring but not an App rewrite.
Candidate for a shared Flutter signaling/media layer: upstream flutter-webrtc/dart-sip-ua plus flutter-webrtc. Selection remains contingent on pinned dependency/build compatibility and a cold-start background-call proof; native OS ownership must not depend on an already-visible Flutter UI. Do not embed a WebView simply to reuse browser JsSIP.
MDD source proof: control/app/softphone_ws.py exposes per-line SIP WSS relay; main.py api_softphone returns provisioning, media/TURN information. engine/templates/pjsip.conf.j2 currently max_contacts=3 and remove_existing=yes; extensions.conf.j2 checks PJSIP_DIAL_CONTACTS but dials the shared endpoint. Multiple clients must be tested for simultaneous registration/ringing, late push registration during ringing, one-answer cancellation and stale/revoked clients.
Codec gate: current MDD template explicitly supports ulaw/alaw and omits opus due to ARM engine transcoder availability. Do not assume Opus or promise higher audio quality without engine codec verification. Media remains MDD-controlled Asterisk bridging IMS, with direct or TURN topology according to MDD provisioning; SIP WSS is not an audio transport.
Background incoming chain: MDD receives carrier call -> send push -> native OS incoming-call presentation -> restore authenticated per-line SIP session -> bind SIP dialog to native call UUID -> answer via SIP -> audio session activation/WebRTC media. Native callback ordering, cancelled call before wake, lock screen, Bluetooth, WiFi/cellular change and TURN-only network require device tests.
Other migration requirements remain intact: MDD alone owns SIM/engines, all auth/readers/devices/SMS/MMS/eSIM/settings move to MDD, NEWONE is source only. Do not continue designing a PCM compatibility bridge as the default while this direction is being resolved.
References verified: https://github.com/flutter-webrtc/dart-sip-ua ; https://jssip.net/documentation/misc/interoperability/ ; https://developer.apple.com/documentation/PushKit/responding-to-voip-notifications-from-pushkit . These establish protocol/library and OS constraints, not project runtime proof.
