# Bounded resident Android late-pickup design (read-only)

Own only android-resident-pickup-plan.md here. Read current android-pickup-disposition.md and MIGRATION_SPEC.md, then actual Android retained native call chain, Dart shared SIP registry and MDD /ws, history and pickup receipt paths. Do not change production/tests or run external services. NEWONE read-only, no commit/push/deploy or extra agents.

Original approved scope requires late registration while ringing and retained native incoming UI, without SSE/PCM. Parent authorizes designing the smallest in-process resident solution using MDD authenticated generic /ws plus same-line reconciliation and receipt-verified SIP pickup. No new FCM provider, cloud service or app, no unconditional auto-answer. Killed-process wake without a provider remains separate unavailable capability, not something a WebSocket can solve.

Specify how the OS incoming call is reported/reserved before user answer, then actual pickup only on user answer when no INVITE bound. Distinguish engine call_id, SIP dialog and native UUID. Cover initial WS/history ordering, reconnect and stale history, duplicate INVITE/push equivalent events, terminal/other-client answer, cancel during receipt/media/start, generation/logout, no credential persistence change, existing SIP normal path and both-app contract consistency. Prefer existing endpoints; if wire changes essential, give exact minimal contract and both consumers' impact. Include file ownership, risk and executable test matrix before implementation. This is design evidence, not claimed support.
