# Frozen migration specification v2 — 2026-10-13
User authorization: original complete migration request; explicit acceptance of SIP/WebRTC recommendation and request to resume. No further architectural approval is required within these bounds.
Architecture: MDD control is the only control plane and SIM authority. MDD creates all line engines. NEWONE is read-only source material. Browser uses JsSIP; both retained Flutter apps use SIP over MDD authenticated WSS with native WebRTC media and retained native OS calling integration. No new PCM gateway/bridge, second gateway, WebView phone or parallel app.
Scope: MDD control/app, engine templates/render only for line/SIP support, MDD web frontend/build integration, tests and docs; both mobile lib/native call integration/dependency manifests/tests. Existing UI layout/design remains; page wiring and honest unsupported/error states may change. Existing mobile uncommitted files are preserved. Source functions are ported with attribution; no deployment of NEWONE.
Non-call shared presentation contract: in-process MDD `/api/mobile/v1` adapters preserve existing page DTOs where necessary. These invoke MDD functions/config/store/locks, never HTTP proxy NEWONE. Core MDD REST routes remain authoritative. API errors must preserve HTTP failure, no empty success placeholders or swallowed 403/404. Unimplemented optional legacy-only features return explicit unsupported status and are recorded as gaps; they do not count as migrated.
Auth: use native MDD `POST /api/auth/client/login`, `GET /api/auth/status`, `POST /api/auth/client/logout`, unwrapped JSON. Login supplies username,password,name,platform,app_version,capabilities. Management apps request `manage_devices`, `manage_esim`, `manage_settings`; valid administrator password is required for issuance. Persist validated capability names on client record and Principal; older tokens have empty capabilities. Do not grant admin principal or wildcard routes. Central route/method/event enforcement. Client status adds client public record (expiry/capabilities) for session restore. No permissive TLS acceptance. Session logout/revocation clears SIP registrations, native state and device push binding.
Stable identity: page device_id is the MDD instance ID for configured lines, NOT USB hardware ID, IMSI, ICCID or ordinal. Reader-only items need explicit reader identity and cannot place calls until MDD provisions a line. ICCID/eUICC AID association remains MDD-owned. Calls refer to MDD instance_id and SIP dialog identity; native call UUID mapping is explicit.
Calls: provision `GET /api/instances/{iid}/softphone` -> enabled,username,password,ws_path,host,realm plus current media provisioning. Use `Authorization: Bearer` on WSS upgrade, `sip` subprotocol. Originate/answer/terminate/DTMF via SIP UA, not old JSON PCM actions or AMI callback-to-browser /call. History via `/api/instances/{iid}/calls`; generic events `/ws` for badges/state; SIP owns call state/audio. Keep compatible ulaw/alaw negotiation; no assumption of Opus transcoding. PushKit wakes/reports native incoming calls immediately, then restores SIP and matches invitation. Android services/Telecom remain. Browser+two mobiles require all-contact ringing, one-answer cancellation, late registration during ringing, revocation tests.
Presentation routes: take each existing non-call `/api/X` page request to `/api/mobile/v1/X` using one route policy. Auth and `/api/instances/*`, `/ws` bypass prefix and use native response shape. Facade success `{data: ...}`, errors `{error:{code,message}}`. Existing DTO definitions in both clients are contract fixtures; field mapping must be explicit and tested. Include dashboard, devices/readers, device overview/controls, SMS conversations/send/delete, eSIM overview/profiles/download progress/switch/disable/delete/nickname, per-card policy, notification/settings. Native push and paired OTP endpoints are migrated to MDD with matching authentication, expiry, redaction and owner cleanup; paired services cannot fall back to old control plane silently.
MDD capability migration: port NEWONE versioned carrier profiles/matching + apply supported operational defaults without overwriting explicit settings; retain MDD ES9+/ES10 lpac, add verified previous-profile compensation where missing; port WeCom/Bark/APNs endpoints/provider semantics into MDD existing dispatcher, retain Telegram/webhook. QMI/module status is projected from MDD-owned hardware sources. OneBoard visual shell/styles/assets are ported from Vue into MDD existing React WebUI, retaining native MDD functional views, cookie/CSRF and JsSIP softphone. Framework translation preserves appearance without a second UI backend.
Validation: meaningful RED then GREEN per behavior; MDD unittest auth/capability/route/DTO/call-template/rollback/provider tests, Python syntax and full regression; both Flutter targeted tests, analyze and Android build when available; OneBoard locked npm install/test/build. Mocked hardware/providers prove software behavior only. No fabricated device proof.
Dependencies allowed: locked SIP UA + Flutter WebRTC and necessary native integration in both mobile pubspec/lock/platform build files; MDD APNs HTTP/2 transport dependencies only if justified/pinned, prefer existing packages; OneBoard source dependencies copied with lock into MDD. No unrelated upgrades or remote latest tools. Configure caches/temp inside allowed roots where possible. Runtime builds may require existing toolchain caches.
