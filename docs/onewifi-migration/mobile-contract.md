MDD is the sole origin and line authority. Page `device_id` is the MDD instance ID; `reader:<physical-id>` is unprovisioned, non-callable, and cannot be passed to `/api/instances/*`. ## Route and identity contract

- Native `POST /api/auth/client/login`, `GET /api/auth/status`, `POST /api/auth/client/logout`, `/api/instances/*`, `/api/readers`, `/api/sim/detect`, `/api/provision`, `/ws`, mobile push endpoint, and exact pickup route are not prefixed. Native responses are unwrapped. Management clients request `manage_devices`, `manage_esim`, `manage_settings`; restore checks those capabilities and revocation clears SIP state.
- Other legacy page `/api/X` routes become `/api/mobile/v1/X` once via `MddMobileContract.route`. Success is `{data: legacy DTO}`; non-2xx errors are not translated into empty success. Explicit unsupported functionality remains disabled in the production UI.
- `GET /api/readers` must be fresh (`stale:false`). Resolve the exact reader name to a unique current PC/SC index immediately before `GET /api/sim/detect?reader_index=...` or `POST /api/provision`; never derive an index from a UI row, physical ID or cached order. A successful provision returns `instance.id`.
- `GET /api/instances/{iid}/softphone` supplies an enabled same-line WSS path, SIP username/password, host/realm, direct/relay ICE policy and current servers. WSS upgrade has bearer Authorization, SIP subprotocol, and normal trust or an origin-scoped SHA256 certificate pin. SIP, not REST, owns dial/answer/end/DTMF/mute/hold. `GET /api/instances/{iid}/calls` is unwrapped history.
- Engine inbound `X-MDD-Call-ID` and push `call_id` must match the same line. A native OS UUID is never a SIP dialog ID. For a late PushKit answer with no invite, `GET /api/mobile/v1/calls/{call_id}/pickup?device_id={iid}` returns `{data:{call_id,pickup_uri,expires_at,device_id}}`; accept only the exact line/call/`mddpickup-<call_id>` and unexpired receipt. After a bounded invite wait and current-registration check, originate same-line SIP pickup with `X-MDD-Mobile-Pickup: <OS UUID>`. The first bound invite/pickup wins; cancel/revocation must prevent later binding. MDD may answer 409 after first answer/cancellation. Outgoing header visibility and real fork timing still need on-device/server observation.
